## 诊断：「难看」到底难看在哪（带证据，视觉病灶审计结论）

上一轮把「骨架」做对了（IA / 状态覆盖 / token 体系 / 焦点环 / reduced-motion 都在），但**皮肤停在「能看」而非「生产级」**。最伤档次的 5 个，按严重度：

1. **零真实图标系统**——全站 18+ 处用 emoji + 几何字符混用当图标：`TopBar` `◆`(logo)/`◐`(主题)/`☰`(汉堡)、`EmptyState ◍`、`IdentityBar ▾`、`ValidateView ⚖`、`ConditionGroup 🗑`、`LoginView 🔐`、`DemoPanel ▶`……`🔐🗑⚖▶` 彩色 emoji 与 `☰◆◐▾◍✕←` 线型符风格割裂、跨 OS 渲染不一致。**这是「廉价感」第一来源。**
2. **纵深近乎为零**——所有卡片 / 表格只用 `--shadow-sm`（≈0.06 alpha）+ 与背景几乎同色的发丝边框；定义好的 `--shadow-md` **组件里一次都没用**；界面通篇扁平。
3. **排版层级太弱**——实际最大标题只有 `--fs-xl`(20px)，只比 14px 正文大 6px；定义好的 `--fs-2xl`(26px) **零使用**；十余处硬编码 px（11/12/12.5/13/22px）绕过 scale，字号系统形同虚设；无 `--fw-bold`(700)。
4. **配色扁平单调**——靛紫 accent 只做实心填色，**全站无一处渐变**；`--accent-2` 紫**定义了从不使用**；多数 primary 按钮**连 hover 都没有**（仅 `Button.vue` 有 brightness）。
5. **几乎没有微交互**——整个应用**只有 2 条 transition**；无 hover 抬升、无卡片阴影过渡、Toast 无入场；大量按钮 / 表格行点上去毫无反馈，界面「静止、无生命」。

附带确认（非病灶，是资产）：`:focus-visible` 全局焦点环 + `prefers-reduced-motion` 压制已到位，保留即可。可达性一处债：`--text-faint #98a0b3` 在白底 ≈ **2.4:1 不达 AA**，却用于大量小号次要文字 —— 本轮顺手修掉。

## 关键前提事实（决定「怎么改最安全」）

- **`tokens.css` 是全站唯一全局 CSS**（`main.ts:5` 单点 import），明/暗双主题 + 全局 reset + a11y 兜底都在这。**改这里的变量「值」→ 传导到所有 scoped 组件，组件零改**。这是最小爆炸半径的注入面。（架构子代理）
- **视觉层是「自由区」**：5 个 E2E + 3 个 Vitest **无任何 `getComputedStyle` / 颜色 / 字号 / 尺寸断言**；oidc 截图仅存档、**无像素对比 baseline**。→ 颜色 / 字号 / 圆角 / 阴影 / hover / 动效可自由改。（约束子代理）
- **硬红线**（碰了直接红）：全部 `data-testid`（尤其 `type-chip-5`、`nav-toggle`）逐字保留；类选择器 `.tr / .text-box / .no-body` 不改名；768 & 390 视口 **body 横向溢出 ≤4px**；侧栏 `<768` 必须 `transform:translateX` 离屏抽屉（不占布局宽度）；`IdentityBar` ≥561 内联可见、actor 文本留在 `auth-bar` 元素内；`OrderSummary` 的 `→` 字符（catalog:60 断言 innerText 含 `→`）；原语 props/variant/slot 名 + tokens 变量名冻结（**加可以、改名/删禁**）。（约束 + 响应式子代理）
- **产品是纯 CRUD**：列表 / 长表单 / KV 详情 / 决策轨迹文本；**零 dataviz**、无现成图表需求。（页面子代理）
- **一致性债**：`Section`/`Field` 两原语**写好却零引用**；同一「主按钮」在 4 个文件有 4 套手写实现；`demos/*`、`condition-tree/*`、`Login` 是绕过原语的「手搓盲区」。（页面 + 架构子代理）

## 决策

### D1 · 视觉方向：Calm Precision（冷静·精密）——中性为主 + 单一强调 + 靠层级取胜
- **备选**：
  - **A. Calm Precision（Linear / shadcn / Vercel 血统）**——冷偏中性色阶 + 单一克制强调 + 可见边框 + 分层柔和阴影 + 强排版层级 + mono 数据一等公民。
  - **B. Vibrant SaaS（渐变 hero + 双色渐变按钮 + 大圆角 + 彩色卡片）**——更「营销/消费」。
  - **C. 保守打磨（仅微调现有靛紫、不换气质）**——风险最低但「难看」病根未除。
- **裁决：A。** 规则/决策引擎控制台的气质应是「工程师信得过的克制」；B 的花哨与「引擎/数据」定位相悖、且渐变/彩卡易显廉价（正是要避开的 AI 通病）；C 治标不治本。A 恰好命中用户点名的 langchain-platform（LangSmith 清爽中性 + brand accent + mono trace）与现代 admin console（Vercel/Linear/Supabase/shadcn）的共性。
- **视觉参考与借鉴点见 FINAL_PLAN §「视觉方向与设计参考」**（每条给「借鉴了什么模式 → 落到本项目哪个 token/组件」）。

### D2 · 强调色：换成「精修靛蓝 `#4f46e5`」为默认，但**由用户在 3 选 1 里拍板**
- 现状 `#6366f1` 是从旧后端 CSS 机械平移、「只加不改」继承来的，**从未按品牌定调**（页面子代理确认）——本轮正是重定它的时机。
- **备选（Artifact 里可实时切）**：`indigo #4f46e5`（推荐，更深更笃定，仍在 AI/规则语境内）/ `cobalt #2563eb`（更「数据/可信」的经典 admin 蓝）/ `violet #7c3aed`（更具品牌辨识度）。
- **裁决：默认 indigo `#4f46e5`，作为「待用户确认的假设」**；三者都已在提案预览里配好明/暗双主题值，选定即定。强调色只是次要杠杆——真正治「难看」的是中性色阶 / 纵深 / 排版 / 图标。

### D3 · 注入架构：token 全量 + 外壳三件套 + 原语打磨 + 新 Icon.vue（架构 A 全量 + B 子集）
- **备选**：A 纯 token 层（1 文件、零组件改、好看上限中）/ B token + 原语深度改造 + 图标层（工作量大、上限高）。
- **裁决：A 全量 + B 只做「每屏可见的公共面」**——即 token 全换 + 外壳三件套（`TopBar`/`SidebarNav`/`AppLayout`）+ 6 个高频原语打磨 + 新 `Icon.vue`。理由：外壳是全站每屏可见、单位投入 ROI 最高（上一轮亦认定「外壳 = 收益最大」）；手搓盲区（demos/condition-tree/Login）按性价比放到**收尾阶段增量下沉**，不阻塞主收益。
- **否决「纯 A」**：改不动结构 → 侧栏选中态、图标、按钮三态、卡片质感都上不去，达不到「生产级」。**否决「B 全量一次做完」**：手搓盲区长尾大、易碰 testid，一次性风险高。

### D4 · 图标方案：新建本地内联 SVG `Icon.vue`（手抄 lucide path，零依赖）
- **备选**：本地内联 SVG 组件 / SVG sprite（`<use>`）/ 图标字体 / 继续 emoji 字形。
- **裁决：本地内联 SVG `Icon.vue`。** 内部维护本地 path 映射（手抄所需 lucide path，**不装 npm 依赖**）、`stroke=currentColor` 随主题联动、只打进用到的图标（可摇树、体积极小）、`/ui/` 内网零 CDN、SVG 可挂 `data-testid` + `aria-label`。
- **合规性判定**：上一轮 FINAL_PLAN Non-goal 写「不引 UI/图标/CSS 组件库」。`Icon.vue` **不引库**（不 `npm i lucide`）、只手抄 path 进自有 SFC，**符合「手写 scoped SFC + tokens.css」约束**——但因它动 DOM（往按钮里塞 `<svg>`），**列为待用户确认项**。
- **否决图标字体**：前置加载 + FOIT/FOUT + 屏读噪声，最不契合约束。**否决 sprite**：多一层构建/`base:'/ui/'` 路径管道，收益不明显。

### D5 · 排版：补字阶与字重，收敛硬编码（token 内完成）
- 页面标题升到 24–26px / 700（启用闲置的 `--fs-2xl`，或加 `--fs-3xl`）；补 `--fw-bold:700`；卡片标题 15–16/600；micro-label 12/600/大写/`.05em`；数据用 `tabular-nums`。
- 十余处硬编码 px 逐步换成 `--fs-*`（收尾阶段随组件打磨一并做，不单独立项）。

### D6 · 圆角收紧 14 → 10（更精密）
- 现 `--radius:14px` 偏圆润；收到 10（`--radius-sm:7`、`--radius-lg:14`）让界面从「圆润」转「工程精密」，贴规则引擎气质。属改值不改名，零风险。**列为可回退项**（若用户偏好圆润可保留 14）。

### D7 · 可选新增：ListView 顶部轻量 stat 指标条（Tremor 风）
- 唯一能引入「指标类」视觉、显著提升生产级感的位置（活动总数 / 已上线 / 待上线 / 今日验证）。**但属新增内容**（非纯视觉皮肤）。
- **裁决：作为可选项，默认做「静态占位版」或不做，由用户拍板。** 若做，数据尽量取自现有列表响应（总数 / 按状态计数），不新增 API。

### D8 · FOUC 加固（可选）：把主题读取内联进 `index.html <head>`
- 现主题写入在 `main.ts` 模块体内（非 `<head>` 阻塞脚本），冷启动有极小闪现窗口。本轮加大明暗对比后闪现更显眼。
- **裁决：可选加固**——在 `index.html <head>` 加一段读 `localStorage['drools-theme']` → 写 `data-theme` 的内联脚本。属结构性极小改动，**列为待确认项**。

### D9 · 死原语处置：本轮启用 `Section` / `Field`
- `EditorView` 手搓的 `.sec-title` / `.fg label` 下沉到 `Section` / `Field`，消除一致性债。属打磨阶段增量，保 testid。

### D10 · 响应式：原样保留，只在「不撑破 4px 溢出」前提下升级
- 断点字面量（767/560/980/760）、抽屉 translateX 机制、44px 触控、z 序、safe-area、`100dvh` **全不动**。视觉升级新增的 padding / 图标 / chip 宽度必须在 768 & 390 下守住 `body.scrollWidth - innerWidth ≤ 4px`。桌面优先；手机「可读不崩」。

## 非目标（Non-goals）

- 不加新功能、不改路由 name/path、不动 API 契约 / store / 业务逻辑 / 条件树语义 / 校验提交流程。
- 不引 UI / CSS 组件库；`Icon.vue` 手抄 path 不算引库（D4）。
- 不重写 `ListView` 表格为 `DataTable`（碰脆弱 `.tr`）；stat 条若做仅为轻量展示（D7）。
- 不改后端、不改 Casdoor 登录页；不做 PWA / 手势 / 独立移动端产品。
- 不改任何 `data-testid`、不改 `.tr/.text-box/.no-body` 类名、不动 tokens 变量名（只改值 + 新增）。
