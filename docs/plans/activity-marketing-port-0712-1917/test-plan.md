# Test Plan

## test-designer 视角

### 单元测试

- `ActivityCommonValidator`：
  - 开始时间晚于结束时间失败。
  - 规则详情为空失败。
  - 金额小于 0 或大于 999999 失败。
- `ConditionNode` 翻译/校验：
  - 合法 `AND/OR` 条件树通过。
  - 非白名单字段失败。
  - 字段不支持的运算符失败。
  - `between` 非双元素失败。
  - 字符串值转义正确。
- `ActivityCandidateFlattener`：
  - 基础层字段覆盖规则层同名字段。
  - `priority` 为空时按默认值处理。
- `RuleCompiler`：
  - 合法 DRL 编译成功。
  - 非法 DRL 返回可读错误。
- `ActivityStackStrategy`：
  - `MAX` 选最大金额。
  - `PRIORITY/MUTEX` 选最小 priority，priority 相同选大金额。
  - `STACK` 累加金额。

### 服务集成测试

建议使用 `@SpringBootTest` + H2 profile。

- 创建活动：
  - 提交基础信息、规则详情、商品绑定、资格条件后，相关表均有记录。
  - 规则编译失败或条件树非法时，所有表均无新增。
- 编辑活动：
  - 旧版本 `isDel=1`，新版本 `version+1/isDel=0`。
  - 已下线活动编辑失败。
  - 已上线活动修改开始时间失败。
- 上下线：
  - 待上线 -> 已上线成功。
  - 已下线活动不参与 `filterBeginActivityIds`。
- 查询优惠：
  - 一个 SPU 绑定多个活动，默认 `MAX` 返回最大金额。
  - `effective=0` 的绑定不参与。
  - 过期活动不参与。
- 资格规则：
  - 地域命中通过。
  - 地域不匹配被淘汰。
  - 用户地区为空时地域规则跳过，行为与设计一致。
- 缓存：
  - 同一版本重复查询不重复编译。
  - 规则版本变化后新查询命中新规则。

### 前端回归测试

当前项目无前端测试框架；实施时建议至少做浏览器手工回归，必要时补 Playwright。

关键路径：

- 打开首页后出现“活动营销”分组。
- 活动创建报表表单所有字段在桌面和移动宽度不重叠。
- 可以添加/删除商品绑定行。
- 可以添加/删除资格条件行。
- 提交后展示活动 id、版本、状态。
- 运行商品优惠验证后展示命中活动、金额、策略、trace。
- 非法输入显示后端错误，不吞掉状态码。

### 异常场景

- 重复提交同一个 `requestId` 不重复创建。
- 并发编辑同一活动只产生一个成功版本，另一个返回冲突。
- 规则编译超时或异常时回退旧逻辑，并记录 trace。
- 数据库连接失败时前端展示错误。
- 空商品绑定、空活动规则、空条件组均按明确错误返回。

### 验收标准

- `./mvnw test` 通过。
- H2 profile 启动成功。
- 前端可完成“创建活动 -> 上线 -> 查询 SPU 优惠 -> 修改规则 -> 再查询 -> 下线 -> 查询不命中”的闭环。
- 规则异常不会造成部分落库。
- 文档中的接口样例与实际 controller request/response 字段一致。
