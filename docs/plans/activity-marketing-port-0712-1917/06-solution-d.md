# 06 Solution D - drools-demo 作为前端与编排壳，后端代理到 mall-shop

## architecture-designer 视角

### 架构

当前项目主要承接前端和演示编排，不复制来源活动逻辑；通过 HTTP client 或本地代理调用运行中的 `mall-shop` 服务。

### 模块职责

- `drools-demo` 前端：报表式活动创建、规则条件、验证视图。
- `drools-demo` 后端：代理层、请求/响应适配、mock 数据补齐。
- `mall-shop`：真实活动逻辑执行。

### 核心流程

1. 启动来源项目 `mall-shop`。
2. 当前项目前端提交活动表单。
3. 当前项目后端将请求转换为来源接口请求。
4. 来源项目执行真实链路，返回结果。
5. 当前项目统一渲染响应与 trace。

### 改动范围

当前项目中等，来源项目不改。但需要能稳定启动来源项目和其依赖。

### 扩展性

适合联调和对照，不适合“在这个项目中放一份逻辑”的原始目标。

### 实施成本

中等到高，取决于来源项目依赖是否可本地启动。

## risk-reviewer 视角

- 兼容性：当前项目侵入较小，但强依赖外部服务。
- 事务：事务在来源项目内，不可由当前项目控制。
- 并发：真实风险可暴露，但难以在 demo 中隔离复现。
- 性能：可观察真实接口，但 demo 本身无法内嵌优化。
- 安全：需要处理代理鉴权、cookie/token、内网配置。
- 数据迁移：不需要迁移，但需要真实库或测试库。
- 灰度与回滚：可验证真实开关，但不满足离线 demo。

## test-designer 视角

需要契约测试和代理错误处理测试，还要准备 mall-shop 测试环境。

## 结论

适合作为方案 A 完成后的“对照模式”，不适合作为主迁移方案。
